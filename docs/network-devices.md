# Сетевое оборудование и средства защиты: что поддерживается

Какие производители и решения проверяет «Харденинг», что именно проверяется, какие уязвимости
известны по БДУ ФСТЭК и какие рекомендации по харденингу даёт система. Данные БДУ — по локальной
копии на 16.10.2026.

## Коротко

- В основном списке **8 решений**: 4 коммутатора и маршрутизатора, 4 межсетевых экрана и VPN-шлюза.
  Отобраны по распространённости в российских сетях, наличию в БДУ и сертификации ФСТЭК.
- Проверяются **две вещи**:
  - конфигурация: пароли, протоколы управления, доступ, журналирование;
  - **версия ПО (прошивки)**: сопоставляется с БДУ ФСТЭК, устаревшая прошивка с известными
    уязвимостями попадает в отчёт.
- Данные собираются тремя способами: по SSH (только команды на чтение), по выгрузке конфигурации,
  по опросу аудитора (для устройств, которые настраиваются только через графическую систему управления).
- Каждая проверка привязана к рекомендации производителя и к пункту УСИ методики анализа
  защищённости ФСТЭК от 25.11.2025.

## Почему эти решения

| Критерий | Зачем |
|---|---|
| Распространённость в России | проверяем то, что реально стоит в сетях заказчиков |
| Есть в БДУ ФСТЭК | можно найти устаревшую прошивку с известными уязвимостями |
| Сертификат ФСТЭК | госсектор и КИИ обязаны ставить сертифицированные средства защиты |
| Открытая документация CLI | без неё нельзя честно написать проверки |

Fortinet и Juniper в БДУ представлены широко, но после ухода из России новых поставок нет, поэтому
в основной список они не включены.

PT NGFW — девятая строка, но в основном списке: это одно решение из двух паков (распознавание по SSH
и опрос по настройкам).

Huawei VRP и MikroTik RouterOS — в плане: паков пока нет. Проверка версии Cisco добавляется в пак
`cisco-ios`: сейчас он проверяет только конфигурацию.

**Выводы по БДУ.**
- Больше всего уязвимостей у **Cisco**: 444 записи по IOS и IOS XE, у 48 есть эксплойт. Устаревший
  IOS — самая частая проблема старых сетей, поэтому проверка версии здесь важнее всего.
- У **MikroTik** 48 уязвимостей, и у 31 из них есть эксплойт: на таких устройствах строились
  ботнеты (Mēris, VPNFilter).
- У **российских решений** записей единицы. Это не значит, что уязвимостей нет: исследователи и
  производители сообщают о них в БДУ реже.
- **Huawei** в БДУ представлен почти только телефонами и ноутбуками (HarmonyOS, EMUI). Уязвимости
  сетевого оборудования Huawei публикуются в бюллетенях Huawei PSIRT и NVD, но в БДУ не попадают, поэтому
  для Huawei сопоставление с БДУ ничего не даст.

## Что есть у ФСТЭК

| Что | Есть ли | Как используется |
|---|---|---|
| БДУ ФСТЭК: уязвимости ПО, включая сетевое оборудование | да | сопоставление версии прошивки (пункт УСИ.1 методики) |
| Методика анализа защищённости от 25.11.2025 | да, общая, не по вендорам | каждая проверка привязана к пунктам УСИ |
| Методика оценки критичности уязвимостей от 30.06.2025 | да | уровень критичности V для найденных уязвимостей |
| Требования к межсетевым экранам, реестр сертифицированных средств | да | указан в описании решения |
| Руководства по харденингу конкретных моделей | **нет** | берём руководства производителей |

Сертификаты ФСТЭК (сверить с реестром на дату защиты):
- Континент 4, ViPNet Coordinator, UserGate NGFW — сертифицированы;
- PT NGFW — сертификат получен в 2025 году;
- Eltex ESR — есть сертифицированные исполнения (справочник CLI 1.5.10 FSTEC);
- Cisco, Huawei, MikroTik — действующих сертификатов нет, но устройства по-прежнему стоят в
  коммерческих сетях.

## Решения подробно

### 1. Cisco IOS / IOS XE

Пак `cisco-ios`, источник — Cisco IOS Hardening Guide.

Проверяется:
- пароли хранятся зашифрованными (`service password-encryption`), задан `enable secret`, нет
  обратимого `enable password`;
- включена модель AAA (`aaa new-model`);
- нет SNMP community `public` / `private`;
- SSH только версии 2, встроенный HTTP-сервер выключен;
- на линиях VTY запрещён Telnet, транспорт задан явно, доступ ограничен списком (`access-class`);
- блокировка входа после серии неудачных попыток (`login block-for`);
- синхронизация времени по NTP.

Рекомендации по харденингу:
1. Убрать Telnet: `line vty 0 15` → `transport input ssh`.
2. Ограничить управление адресами администраторов: `access-class MGMT in`.
3. `aaa new-model` и вход через TACACS+ / RADIUS вместо локальных паролей.
4. `enable secret` вместо `enable password`, `service password-encryption`.
5. `no ip http server`, `ip ssh version 2`, сменить или удалить SNMP community по умолчанию.
6. `login block-for 120 attempts 5 within 60`.
7. Обновить IOS до версии, в которой закрыты уязвимости из отчёта.

### 2. Huawei VRP (в плане)

Источник — Huawei Security Hardening Guide для коммутаторов и маршрутизаторов.

Будет проверяться:
- Telnet и FTP выключены, используется STelnet (SSH);
- доступ к VTY ограничен ACL, включён AAA;
- SNMPv3 вместо v1/v2c;
- пароли хранятся в виде `irreversible-cipher`;
- журнал отправляется на syslog-сервер (`info-center`);
- NTP с аутентификацией.

Версия VRP будет собираться для отчёта, но сопоставить её с БДУ не получится: сетевых продуктов
Huawei в БДУ нет.

### 3. Eltex ESR

Пак `eltex-esr`, источник — Eltex ESR Hardening Guide.

Проверяется:
- изменён пароль `admin`, включён запрос смены пароля по умолчанию;
- длина пароля не меньше 8 символов, срок действия пароля ограничен;
- Telnet выключен, доступ к SSH ограничен адресами, отключён устаревший обмен ключами `dh-group1-sha1`;
- из зоны `untrusted` к самому маршрутизатору нет разрешающих правил без ограничения источника;
- межсетевой экран не отключён ни на одном интерфейсе, включена защита от подмены адреса;
- вход через внешний AAA, команды администраторов пишутся в журнал, журнал уходит на syslog;
- нет SNMP v1/v2c, время по NTP, NTP broadcast-клиент выключен.

Рекомендации по харденингу:
1. Сменить пароль `admin`, лучше заменить его персональными учётными записями.
2. `security passwords default-expired`, минимальная длина пароля 8 символов.
3. Выключить Telnet, задать `ip ssh access-addresses`.
4. Проверить правила `security zone-pair untrusted self`: разрешать управление только с адресов
   администраторов. На учебном vESR так был открыт SSH из внешней зоны.
5. Только SNMPv3, журнал на внешний syslog, `syslog cli-commands`.

Версия ПО и модель (`show system`) сопоставляются с БДУ (продукт `esr-200` и другие).

### 4. Eltex MES

Пак `eltex-mes`, источник — руководство по эксплуатации MES 6.6.12.1 и «Настройки безопасности MES».

Проверяется:
- Telnet и веб-интерфейс по HTTP выключены (по умолчанию на MES они включены);
- управление ограничено списком (`management access-class`);
- требования к сложности пароля, блокировка после неверных попыток;
- нет SNMP community по умолчанию;
- вход через TACACS+ / RADIUS, команды администраторов регистрируются;
- журнал на syslog, время по NTP.

Главная рекомендация — выключить то, что включено с завода: Telnet, HTTP, SNMP `public`.

Версия ПО сопоставляется с БДУ.

### 5. MikroTik RouterOS (в плане)

Источник — руководство MikroTik «Securing your router».

Будет проверяться:
- выключены службы `telnet`, `ftp`, `www`, `api`; `winbox` и `ssh` доступны только с адресов
  администраторов (`/ip service ... address=`);
- пользователь `admin` переименован или удалён, у всех учётных записей есть пароль;
- выключены MAC-сервер и MAC-Winbox, обнаружение соседей (`neighbor discovery`) и bandwidth-test;
- в межсетевом экране есть правило `drop` для входящего трафика из WAN;
- выключены SOCKS и web proxy, если они не нужны;
- журнал на syslog, время по NTP.

Версия RouterOS (`/system resource print`) будет сопоставляться с БДУ: 48 уязвимостей.

Пак можно проверить на реальной системе: у MikroTik есть бесплатный образ CHR для виртуальной машины.

### 6. Континент 4 (Код Безопасности)

Пак `kontinent-4`, источник — документация 4.2.1.

Сбор только по опросу: настройки задаются в графическом Менеджере конфигурации ЦУС, выгрузки нет.

Проверяется:
- сменён пароль локального меню (заводской `Passgrub.1`) и BIOS (заводской `123456`);
- политика паролей администраторов: длина, блокировка после неверных попыток;
- администраторы работают под персональными учётными записями с ролями;
- SSH к локальному меню выключен или ограничен адресами;
- тайм-аут сеанса не больше 15 минут;
- SNMP выключен или работает по v3;
- журнал отправляется на syslog.

Главная рекомендация — сменить заводские пароли: они опубликованы в документации.

Версия, введённая аудитором, сопоставляется с БДУ: есть уязвимости версий до 4.2.1.

### 7. ViPNet Coordinator HW / KB 4 (ИнфоТеКС)

Пак `vipnet-coordinator`, источник — справочник команд 4.2.0.

Проверяется:
- SNMP community не заводские;
- включён антиспуфинг (по умолчанию выключен);
- блокируются протоколы, отличные от IP, ARP и RARP;
- журнал ведётся и отправляется на удалённый узел;
- тайм-аут сеанса командного интерпретатора.

Версия сопоставляется с БДУ.

### 8. UserGate NGFW 7

Пак `usergate-ngfw`, источник — руководство администратора 7.1.

Проверяется:
- из зоны `Untrusted` управление (веб-консоль, CLI, XML-RPC, SNMP) не открыто для любых адресов;
- требование сложного пароля для администраторов, длина пароля не меньше 8 символов, блокировка
  после 5 неверных попыток;
- в зоне `Untrusted` включены защита от IP-спуфинга и от SYN-флуда.

Главная рекомендация — не открывать управление в зоне `Untrusted`.

Версию CLI не показывает, поэтому с БДУ она не сопоставляется, хотя записей там 12, и у 10 из них
есть эксплойт. Решение — добавить версию как вопрос опроса.

### 9. PT NGFW 1.11 (Positive Technologies)

Паки `pt-ngfw` и `pt-ngfw-settings`, источник — справочный портал 1.11.

По SSH устройство распознаётся и считывается версия. Настройки проверяются по опросу: они задаются в
веб-интерфейсе и API, а методы API публикуются только на самой системе управления.

Проверяется:
- нет разрешающего правила «любой — любой — любой сервис»;
- администраторы работают под персональными учётными записями с ролями, а не под `admin`;
- аутентификация через LDAP или RADIUS;
- SNMP выключен или работает по v3;
- события передаются сборщику журналов.

Версия сопоставляется с БДУ.

## Ограничения

- Все сетевые паки в статусе `draft`. Проверки написаны по документации производителя и проверены на
  образцах вывода команд, на живых устройствах не запускались: образы большинства решений
  выдаются только по запросу или партнёрам. Выгрузка конфигурации с реального устройства переводит
  пак в `baseline`.
- Опрос (Континент, PT NGFW) менее надёжен, чем чтение конфигурации. Поэтому снимок помечается
  «по опросу», а комментарий аудитора сохраняется как свидетельство.
- Сопоставление с БДУ находит только то, что есть в БДУ: у российских решений записей мало, у Huawei
  сетевого оборудования их нет совсем.
