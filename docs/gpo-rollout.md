# Раскатка агента «Харденинг» на Windows через GPO

Инструкция для администратора домена. Цель — поставить агент примерно на 500 компьютеров одной политикой, партиями, без обхода рабочих мест.

Сервер: `https://audit.hardening-audit.ru`.
Текущая опубликованная версия агента на момент этой инструкции: `2026.11.08-a237722`. Перед копированием файлов сверьте её с `https://audit.hardening-audit.ru/downloads/version.json`: если там уже новее, берите ту, что в `version.json`.

Сценарий, который выполняет ПК: [`deploy/windows/gpo/gpo-startup.ps1`](../deploy/windows/gpo/gpo-startup.ps1). Шаблон строки параметров: [`deploy/windows/gpo/gpo-parameters.txt`](../deploy/windows/gpo/gpo-parameters.txt). Щелчки в оснастке и Ansible для Linux подробнее разобраны в [agent-domain-install.md](agent-domain-install.md).

## Откуда брать файлы

| Файл | Где лежит |
|---|---|
| `gpo-startup.ps1` | В git: `deploy/windows/gpo/gpo-startup.ps1`. На сервере: `https://audit.hardening-audit.ru/downloads/gpo-startup.ps1`. Туда его кладёт `deploy/publish_agent.sh` |
| `hardening-agent.exe` | В git его нет. На сервере: `https://audit.hardening-audit.ru/downloads/hardening-agent.exe` (каталог `deploy/generated/downloads/`, его наполняет `deploy/publish_agent.sh` из сборки CI). Запасной источник — файл релиза GitHub: workflow [`.github/workflows/windows-release.yml`](../.github/workflows/windows-release.yml) по тегу `agent-*` или `v*` прикладывает `hardening-agent.exe` |
| Строка параметров | Страница «Агенты» собирает её в момент создания ключа площадки. Образец без секрета — `deploy/windows/gpo/gpo-parameters.txt` |

Отпечаток ключа сервера (SPKI, SHA-256), с которым агент должен ходить на боевой сертификат:

```text
sha256//F2IS+EuQnazu4oq6kt82+KkSARv4DiztB0hU9vOzdsU=
```

Живое значение — поле `server_pin` в `version.json`. Страница подставляет его в `-Pin`. Если сертификат сменят, в политику попадает новый `server_pin`, а не строка из этого абзаца. Отпечаток, который компьютер увидел через подмену сертификата, в `-Pin` не вписывают: страница берёт пин из файла, который сформировал сервер, а не из сертификата браузера администратора.

## Ключ площадки

1. Войдите на `https://audit.hardening-audit.ru` (пароль и код 2FA).
2. Выберите организацию. Если организации ещё нет, суперадминистратор создаёт её на странице «Пользователи и организации» и переходит по ссылке на «Агенты».
3. Блок «Новый ключ площадки»: имя площадки, срок **90 дней** на время раскатки, кнопка «Создать ключ».
4. Ключ вида `yak_...` показывается один раз. Сервер хранит только его хэш. На этом же экране — готовая строка параметров и кнопка «Скачать пакет GPO».

Архив собирается в браузере и содержит:

- `gpo-parameters.txt` — строка с адресом, ключом, открытым ключом паков, пином и паузами;
- `README.txt` — короткие шаги, без повторения ключа;
- `gpo-startup.ps1` и `hardening-agent.exe`, если они уже опубликованы и их SHA-256 совпал с `version.json`.

Кнопка «Скрыть ключ» и смена организации убирают секрет с экрана. Повторно сайт его не выдаст: нужен новый ключ.

На компьютере сценарий пишет ключ в `C:\ProgramData\HardeningAgent\site.key`. Каталог и файл доступны только SYSTEM (`S-1-5-18`) и группе администраторов (`S-1-5-32-544`). В аргументы задачи «Hardening agent bootstrap» ключ не входит, в `gpo-startup.log` не пишется. После регистрации `site.key` удаляется, остаётся `host.json` с ключом этого ПК. В SYSVOL строка параметров видна пользователям домена, поэтому срок ключа короткий. Уже зарегистрированные ПК работают своим ключом и после отзыва ключа площадки.

Строка, которую страница кладёт в политику (ДОМЕН администратор заменяет на DNS-имя домена):

```text
-Server https://audit.hardening-audit.ru -SiteKey yak_... -PackPublicKey ... -Pin sha256//F2IS+EuQnazu4oq6kt82+KkSARv4DiztB0hU9vOzdsU= -Share \\ДОМЕН\NETLOGON\Hardening -InitialJitterMaxSeconds 900 -RetryBudgetSeconds 1800 -BootstrapEveryMinutes 15 -BootstrapRandomDelayMinutes 15
```

`-Pin` можно повторить или перечислить через запятую, если заранее есть проверенный резервный отпечаток. Пустой список у ещё не зарегистрированного ПК один раз берёт `server_pin` из `version.json`. После `TLS_PIN_MISMATCH` этот источник запирается файлом `pin-mismatch.lock`.

## Перед раскаткой: антивирус и периметр

Сделайте это до пилота. Иначе проверка защищённых соединений подменит сертификат сервера, и регистрация остановится с кодом `TLS_PIN_MISMATCH` (выход агента 76).

Подтверждённый случай — Kaspersky Endpoint Security. Издатель на ПК: «Kaspersky Endpoint Security Personal Certification Authority». В политике KES в Kaspersky Security Center добавьте домен `audit.hardening-audit.ru` в доверенные адреса. Как это сделать в консоли MMC, написано в справке KES для Windows 12.8, статья «Исключение защищенных соединений из проверки»: <https://support.kaspersky.com/KESWIN/12.8/ru-RU/175151.htm>. Шаги из статьи: Политики → свойства политики → Общие настройки → Настройки сети → Проверка защищенных соединений → Настроить доверенные адреса → Добавить. Запись домена покрывает этот домен и `www`, маска `*.domain` — поддомены. Если стоит другой выпуск KES, откройте статью для его номера.

Агент ходит на сервер сам, не из браузера. Если после исключения домена на пробных ПК код `TLS_PIN_MISMATCH` остался, добавьте приложение в доверенные программы и отметьте «Не проверять сетевой трафик». Статья «Формирование списка доверенных программ»: <https://support.kaspersky.com/keswin/11/ru-RU/123510.htm>. Путь: `C:\Program Files\Hardening\hardening-agent.exe`. Сертификат Kaspersky в `-Pin` не кладут.

Любой другой антивирус или шлюз, который вскрывает HTTPS, нуждается в таком же исключении домена сервера. Периметровый межсетевой экран этой инфраструктуры — Континент 4. До пилота проверьте, что для `audit.hardening-audit.ru` инспекция TLS на нём выключена. Путь по меню зависит от версии; руководство — на <https://docs.securitycode.ru/>. Рядом тем же правилом закрывают UserGate, Dr.Web и ESET, если они стоят на пути. Подсказка `TLS_INSPECTION` в журнале называет продукт, который подменил сертификат.

С любого ПК домена:

```powershell
Test-NetConnection audit.hardening-audit.ru -Port 443
```

Ожидается `TcpTestSucceeded : True`. Если интернет только через прокси, в строку параметров дописывают `-Proxy http://proxy.corp:3128`. Агент работает от SYSTEM и прокси браузера не видит.

## Подготовка NETLOGON

Папка `NETLOGON` есть на каждом контроллере и читается компьютерами домена. Так 500 ПК не качают exe из интернета: сценарий берёт файл из `-Share` и сверяет SHA-256 с `version.json`.

На контроллере домена, PowerShell от администратора. Если скачали архив со страницы «Агенты», скопируйте из него `gpo-startup.ps1` и `hardening-agent.exe` и всё равно сверьте суммы с сервером:

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$server = 'https://audit.hardening-audit.ru'
$share = "\\$($env:USERDNSDOMAIN.ToLower())\NETLOGON\Hardening"
New-Item -ItemType Directory -Force -Path $share | Out-Null
$ver = Invoke-RestMethod "$server/downloads/version.json" -UseBasicParsing
foreach ($p in 'windows','windows-gpo') {
  $f = $ver.files | Where-Object platform -eq $p
  Invoke-WebRequest "$server/downloads/$($f.name)" -OutFile (Join-Path $share $f.name) -UseBasicParsing
  $ok = (Get-FileHash (Join-Path $share $f.name)).Hash.ToLower() -eq $f.sha256
  '{0}  версия {1}  контрольная сумма совпала: {2}' -f $f.name, $f.version, $ok
}
"Папка: $share"
```

Обе строки должны закончиться `контрольная сумма совпала: True`. Путь вида `\\corp.local\NETLOGON\Hardening` подставьте в строку параметров вместо `\\ДОМЕН\NETLOGON\Hardening`.

Если у контроллера нет выхода в интернет, скачайте оба файла в браузере с любого ПК со страницы «Агенты» (или из архива пакета) и скопируйте в эту папку. Компьютеры всё равно сверят файл с сервером.

## Групповая политика

Одна политика, два элемента с одной и той же строкой параметров.

1. `gpmc.msc` → лес → домен → «Объекты групповой политики» → создать `Харденинг — агент`. Пока ни к чему не привязывать.
2. Изменить политику.

Автозагрузка (то, что подхватывает каждый включённый ПК):

1. Конфигурация компьютера → Политики → Конфигурация Windows → Сценарии (запуск/завершение).
2. Дважды щёлкните «Автозагрузка».
3. Вкладка **«Сценарии PowerShell»** (не «Сценарии») → Добавить.
4. Имя сценария: `\\corp.local\NETLOGON\Hardening\gpo-startup.ps1` (ваш домен).
5. Параметры сценария: строка со страницы «Агенты», целиком, в одну строку, с уже подставленным путём NETLOGON.

Немедленная задача ставит агент без перезагрузки, при фоновом обновлении политики (90–120 минут, или сразу после `gpupdate`):

1. Конфигурация компьютера → Настройка → Параметры панели управления → Назначенные задания → Создать → Немедленная задача (Windows 7 и выше).
2. Имя `Hardening agent install`, пользователь `SYSTEM`, «Выполнить с наивысшими правами».
3. Действие «Запуск программы», программа `powershell.exe`, аргументы: `-NoProfile -ExecutionPolicy Bypass -File "\\corp.local\NETLOGON\Hardening\gpo-startup.ps1"` и через пробел та же строка параметров.

Политика выполнения PowerShell (ExecutionPolicy) отдельно не меняется: сценарии групповой политики выполняются и при настройке по умолчанию.

Что делает сценарий. Автозагрузка сеть не ждёт и вход не держит: пишет `site.key`, создаёт задачу «Hardening agent bootstrap» (повтор каждые 15 минут плюс случайные 0–15 минут) и выходит с кодом 0. Задача ставит exe, регистрирует ПК со случайной паузой до 15 минут (`-InitialJitterMaxSeconds 900`), при обрыве повторяет сеть до 30 минут (`-RetryBudgetSeconds 1800`). После `host.json` создаётся задача «Hardening agent» (каждый день в 07:30, разброс до 2 часов) и задача «Hardening agent spool», `site.key` удаляется, bootstrap снимается. Первый отчёт уходит в тот же день.

## Расписание и окно сервера

Сервер площадки ночью выключен: примерно с 18:30 до 07:00 по времени Екатеринбурга. Ночной сбор с ПК, который оставлен включённым, до сервера не доходит. Агент повторяет связь около 30 минут, кладёт отчёт в `C:\ProgramData\HardeningAgent\spool` (не больше 50 файлов и 30 дней) и до следующего ежедневного запуска больше не пробует. Утром отчёт есть в основном у тех ПК, которые включают и тем самым ловят пропущенный запуск (`StartWhenAvailable`).

Задача «Hardening agent» поэтому стартует днём: каждый день в **07:30** по локальному времени ПК, случайная задержка до 2 часов (`RandomDelay` `PT2H`). Отчёты приходят с 07:30 до 09:30, когда сервер уже включён. Задача по-прежнему от SYSTEM, с `StartWhenAvailable` и `MultipleInstances = IgnoreNew`, лимит одного запуска — 1 час. Время и разброс заданы в одном месте, в параметрах `gpo-startup.ps1`: `-CollectTime` (по умолчанию `07:30`) и `-CollectRandomDelayHours` (по умолчанию `2`). В строку параметров политики их можно не писать. `-Schedule Weekly` переносит сбор на понедельник на то же время.

Вторая задача, «Hardening agent spool», досылает уже лежащие в очереди файлы. Команда — `hardening-agent.exe flush-spool`. Полный сбор она не запускает, даже если отчёт за сегодня уже ушёл. Повтор каждые 30 минут плюс случайные 0–30 минут, окно 10 часов от того же `-CollectTime` (примерно до 17:30–18:00, пока сервер ещё включён). Пустая очередь или недоступный сервер — выход с кодом 0, без текста и без получасовых повторов внутри одного запуска: следующий получасовой запуск попробует снова. Две досылки сразу не идут (`IgnoreNew`). Пока идёт полный сбор, замок на каталоге очереди не даёт отправить один и тот же файл дважды.

Уже стоящие 171 ПК получают это без ручной правки задач. Строку параметров в политике менять не нужно. После того как в `\\ДОМЕН\NETLOGON\Hardening` лежат новые `gpo-startup.ps1` и `hardening-agent.exe` (оба из `/downloads/` после `deploy/publish_agent.sh`, SHA-256 совпадает с `version.json`), срабатывает один из двух путей:

1. Немедленная задача политики (`Hardening agent install`) при фоновом обновлении политики, обычно 90–120 минут, или сразу после `gpupdate /target:computer /force`. Перезагрузка не нужна.
2. Сценарий автозагрузки при следующей загрузке ПК, если немедленной задачи нет или ПК был выключен.

Сценарий снова создаёт задачу bootstrap и сразу выходит. Bootstrap видит `host.json`, хост заново не регистрирует, exe обновляет, только если SHA-256 отличается, и переписывает задачи планировщика, если определение другое: время, разброс, аргументы, лимит или сама задача досылки. Совпавшее определение даёт в журнале `code=TASK_UNCHANGED` и не стартует первый сбор второй раз. Старая задача на ночной час этим сравнением не считается той же и заменяется. Если опубликованный exe ещё без команды `flush-spool`, дневной сбор всё равно ставится, а задача досылки пропускается (`code=SPOOL_SKIPPED`) до следующей публикации exe. ПК, который не выключают на ночь, подхватывает дневной сбор в тот же день, когда до него дошла политика, и не ждёт ещё одной ночи.

## Применение: партии

1. Пилот: подразделение примерно на **10** ПК, связать политику «Харденинг — агент». На пробном ПК от администратора: `gpupdate /target:computer /force`. Перезагрузка не обязательна, если в политике есть немедленная задача.
2. В журнале пилота нет `TLS_PIN_MISMATCH`, регистрация и первый отчёт есть. Пауза **5 минут**.
3. Следующее подразделение примерно на **50** ПК. Снова пауза 5 минут. В nginx смотрят p95 `rt` на `/api/agent/enroll` и `/api/ingest`: пачки 429, 503 и 5xx быть не должно.
4. Дальше партии по **100** ПК. Весь домен одним `gpupdate` не включают.
5. Серверы — отдельным решением их владельцев.

Лимиты nginx из-за этой раскатки не увеличивают. Если партия встала на `TLS_PIN_MISMATCH`, смотрят сертификат в той же строке журнала и чинят исключение антивируса или Континента 4.

## Как проверить, что ПК встал

На сайте:

- «Агенты» → «Хосты»: имя компьютера, свежая «Последняя связь».
- Текущий прогон («Сканирования»): у этого хоста есть снимок после первого сбора. Первый отчёт появляется после случайной паузы, не в ту же секунду, что регистрация.

На ПК, PowerShell от администратора:

```powershell
Get-Content C:\ProgramData\HardeningAgent\gpo-startup.log -Encoding UTF8
Get-ScheduledTask -TaskName 'Hardening agent bootstrap' -ErrorAction SilentlyContinue
Get-ScheduledTaskInfo 'Hardening agent' | Format-List LastRunTime, LastTaskResult
Test-Path C:\ProgramData\HardeningAgent\host.json
Test-Path C:\ProgramData\HardeningAgent\site.key
```

Журнал сразу содержит `stage=startup code=TASK_SCHEDULED`. После паузы — `stage=enroll code=OK` и путь к `host.json`. `LastTaskResult` задачи «Hardening agent» равен 0. Ключа площадки в файле журнала нет. `site.key` после успешной регистрации отсутствует. Пока регистрация не прошла, задача «Hardening agent bootstrap» есть, а `host.json` ещё нет: это ожидание, не повод ставить агент вручную.

Кто ещё без агента: «Агенты» → «Охват», список из `Get-ADComputer ... | Export-Csv`.

## Если что-то пошло не так

Смотрят `C:\ProgramData\HardeningAgent\gpo-startup.log`.

| Что видно | Что сделать |
|---|---|
| `code=TLS_PIN_MISMATCH`, выход агента **76**, рядом `code=TLS_INSPECTION` | Сертификат подменён. В строке журнала есть subject, issuer, serial, SAN. Для Kaspersky — исключение домена по статье 175151 и при необходимости доверенная программа по статье 123510. Для периметра — выключить инспекцию TLS домена на Континенте 4. В `-Pin` попадает только `server_pin` из `version.json` или заранее проверенный резерв. Увиденный на проводе отпечаток туда не переносят. Запрос в этом запуске не повторяется; после исключения домена bootstrap зарегистрирует ПК сам |
| Ответ **429** и заголовок `Retry-After` | Сервер просит подождать. Агент повторяет запрос внутри `-RetryBudgetSeconds` (1800 секунд), `Retry-After` — нижняя граница паузы и не больше 300 секунд. После бюджета выход **75** (`ENROLL_TRANSIENT`), задача bootstrap повторит через 15–30 минут. Лимиты nginx не поднимают |
| Таймаут, `code=VERSION_UNAVAILABLE`, `code=None` | Скачивание `version.json` обрывается за 60 секунд, либо нет маршрута до порта 443. Проверяют `Test-NetConnection` и, если выход только через прокси, дописывают `-Proxy`. Перезагрузка не нужна: bootstrap повторит сам |
| `code=SHA256_MISMATCH` | В NETLOGON файл, который не совпал с опубликованным. Заново кладут пару с `/downloads/` или из архива, собранного страницей после успешной сверки |
| `code=ENROLL_REJECTED`, выход 1 | Ключ истёк, отозван или имя уже занято отозванным хостом. Новый ключ — новой строкой в обоих элементах политики. Занятое имя освобождают кнопкой «Удалить регистрацию» |
| Нет каталога `C:\ProgramData\HardeningAgent` | Политика до ПК не дошла. `gpresult /r /scope computer` должен показать «Харденинг — агент» |
| ПК есть в «Хостах», отчёта в прогоне нет | Первый сбор ещё в паузе до 15 минут, либо задача «Hardening agent» завершилась не нулём. Ждут `LastTaskResult` и хвост журнала |

## Как обновить агент позже

1. Дождитесь, пока `version.json` покажет новую версию. Exe по-прежнему берётся с `/downloads/hardening-agent.exe` или из релиза по тегу, не из git. Для дневного сбора и `flush-spool` нужны и новый сценарий, и новый exe: `deploy/publish_agent.sh` после зелёной сборки workflow «Windows packs».
2. Замените в `\\ДОМЕН\NETLOGON\Hardening` файлы `gpo-startup.ps1` и `hardening-agent.exe` вместе. Компьютеры сверят SHA-256 сами. Совпавший exe заново не копируется. Новый exe в папке при старом `version.json` сценарий не поставит (`SHA256_MISMATCH`), задачи останутся прежними.
3. Строку параметров в политике можно оставить. `-CollectTime 07:30` и `-CollectRandomDelayHours 2` уже стоят по умолчанию. Менять `-Pin` нужно, когда сменился сертификат сервера и новый `server_pin` проверен.
4. На пилоте: `gpupdate /target:computer /force`. В журнале — `TASK_UPDATED` и `SPOOL_UPDATED`, повторный запуск — `TASK_UNCHANGED`. Задачу «Hardening agent» руками не удаляют.

Уже зарегистрированные компьютеры для обновления снимать не нужно. У них свой ключ в `host.json`, файл `site.key` к этому моменту удалён. С политикой их не «переустанавливают вручную».

## Как убрать агент

С одного компьютера, который больше не должен отчитываться:

1. Выведите его из области действия политики (или отвяжите политику, если убираете агент со всех).
2. PowerShell от администратора:

```powershell
Unregister-ScheduledTask -TaskName 'Hardening agent bootstrap' -Confirm:$false -ErrorAction SilentlyContinue
Unregister-ScheduledTask -TaskName 'Hardening agent spool' -Confirm:$false -ErrorAction SilentlyContinue
Unregister-ScheduledTask -TaskName 'Hardening agent' -Confirm:$false
Remove-Item -Recurse -Force 'C:\Program Files\Hardening','C:\ProgramData\HardeningAgent'
```

3. На сайте удалите регистрацию этого имени, если имя нужно занять снова.

Компьютеры, которые продолжают работать, этими командами не трогают. Отзыв ключа площадки после окончания раскатки их не останавливает.
