# Агент «Харденинг» в домене: пошаговая установка

Обновлено 2026-10-30. Онлайн-версия с комментариями: https://claude.ai/artifact/LVUXBmJueVnTDTopfMzTx6

Инструкция для администратора домена: как за один день поставить агент на сотни Windows-ПК через групповую политику и на Linux-машины через Ansible. Каждый шаг проверен на стенде: домен lab.local, Windows Server 2025 и Windows 11. Справочник по параметрам агента — [agent-install.md](agent-install.md).

## Как это устроено

Вы один раз настраиваете групповую политику, а дальше каждый ПК ставит агент сам. Ходить по рабочим местам и что-то запускать руками не нужно. Сотрудникам ничего устанавливать и настраивать тоже не нужно.

Что происходит на каждом ПК:

1. ПК получает групповую политику и от имени SYSTEM запускает сценарий `gpo-startup.ps1`.
2. Сценарий берёт `hardening-agent.exe` из общей папки домена. Перед установкой он сверяет SHA-256 файла с сервером: подменённый файл не установится.
3. Агент регистрирует ПК на сервере по ключу площадки и получает собственный ключ этого ПК.
4. В планировщике заданий создаётся задача «Hardening agent»: каждый день в 03:00 или раз в неделю, с разбросом до часа.
5. Сразу запускается первая проверка. ПК появляется в веб-интерфейсе через 1–2 минуты.

Повторный запуск сценария ничего не ломает. Если агент уже стоит и ПК зарегистрирован, сценарий просто выходит. Новую версию агента он поставит сам, когда её опубликуют на сервере.

Связь идёт только от ПК к серверу `https://audit.hardening-audit.ru` (порт 443). Открывать входящие порты на ПК не нужно.

## Что подготовить

Работать нужно за контроллером домена (или ПК с RSAT) под учётной записью из группы «Администраторы домена». Вся настройка занимает около 30 минут.

| Что | Зачем | Где взять или как проверить |
| --- | --- | --- |
| Адрес сервера | Куда агенты отправляют отчёты | `https://audit.hardening-audit.ru` |
| Вход в веб-интерфейс с 2FA | Выпустить ключ площадки, смотреть результаты | Учётная запись администратора организации |
| Доступ с ПК на порт 443 сервера | Без него агент не зарегистрируется | На любом ПК: `Test-NetConnection audit.hardening-audit.ru -Port 443` → `TcpTestSucceeded : True` |
| Корпоративный прокси (если есть) | Агент работает от SYSTEM и не видит прокси из настроек браузера | У сетевого администратора: адрес вида `http://proxy.corp:3128` |
| Подразделение (OU) с рабочими станциями | К нему привязывается политика | Оснастка «Пользователи и компьютеры Active Directory» |
| Согласование сбора ПДн (необязательно) | Имя сотрудника за ПК и его группы — персональные данные | У ответственного за ПДн; без него параметр `-CollectIdentity` не включать |

Изменять политику выполнения PowerShell (ExecutionPolicy) не нужно. Сценарии групповой политики выполняются и при настройке по умолчанию, это проверено на Windows 11.

## Шаг 1. Ключ площадки

Ключ площадки — это один пароль на все ПК организации. По нему каждый ПК регистрируется на сервере один раз.

1. Откройте `https://audit.hardening-audit.ru` и войдите (пароль + код из приложения 2FA).
2. Выберите организацию и откройте в меню страницу **«Агенты»**.
3. В блоке **«Новый ключ площадки»** заполните поле **«Площадка»**, например `Головной офис, домен corp`. В поле **«Срок действия»** выберите **90 дней**.
4. Нажмите **«Создать ключ»**. Ключ вида `yak_...` показывается **один раз**. Сразу скопируйте его в Блокнот.
5. Ниже на той же странице, в блоке **«Открытый ключ подписи паков»**, скопируйте вторую строку. Она заканчивается на `=`, это не секрет.

Результат шага: в Блокноте две строки — ключ площадки и открытый ключ паков.

Почему срок короткий: ключ будет лежать в параметрах групповой политики, а их может прочитать любой сотрудник домена. Уже зарегистрированные ПК продолжают работать и после истечения ключа: у каждого свой ключ. Когда раскатка закончена, ключ площадки можно отозвать на той же странице.

## Шаг 2. Общая папка с агентом

Агент кладётся в папку `NETLOGON` домена. Она есть в каждом домене, копируется на все контроллеры и читается всеми ПК. Так 500 ПК не качают файл из интернета.

1. На контроллере домена нажмите «Пуск», введите `PowerShell`, щёлкните правой кнопкой → **«Запуск от имени администратора»**.
2. Вставьте целиком и нажмите Enter (ничего менять не нужно — имя домена подставится само):

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$server = 'https://audit.hardening-audit.ru'
$share = "\\$($env:USERDNSDOMAIN.ToLower())\NETLOGON\Hardening"
New-Item -ItemType Directory -Force -Path $share | Out-Null
$ver = Invoke-RestMethod "$server/downloads/version.json" -UseBasicParsing
foreach ($p in 'windows','windows-gpo') {
  $f = $ver.files | Where-Object platform -eq $p
  Invoke-WebRequest "$server/downloads/$($f.name)" -OutFile (Join-Path $share $f.name) -UseBasicParsing
  $ok = (Get-FileHash (Join-Path $share $f.name)).Hash.ToLower() -eq $f.sha256
  '{0}  версия {1}  контрольная сумма совпала: {2}' -f $f.name, $f.version, $ok
}
"Папка: $share"
```

Результат шага — две строки с `контрольная сумма совпала: True` и путь к папке, например `\\corp.local\NETLOGON\Hardening`. Запишите этот путь, он понадобится в шаге 3.

Если у контроллера нет интернета, скачайте `hardening-agent.exe` и `gpo-startup.ps1` в браузере на любом ПК. Они лежат на странице «Агенты» в блоке скачивания. Потом скопируйте их в эту папку. Сами ПК всё равно сверят файл с сервером.

Когда выйдет новая версия агента, запустите эти команды ещё раз: ПК обновятся сами. Пока старый файл лежит в папке, ПК его не поставят: его сумма уже не совпадает с опубликованной.

## Шаг 3. Групповая политика

Одна политика, в ней два элемента с одинаковыми параметрами:

- **Немедленная задача** ставит агент без перезагрузки ПК. Срабатывает при фоновом обновлении политик, в течение 90–120 минут.
- **Сценарий автозагрузки** проверяет агент при каждом включении ПК: обновляет его и доставляет на ПК, пропустившие задачу.

### 3.1. Соберите строку параметров

Скопируйте строку в Блокнот и замените три вещи: `corp.local` (дважды) — на ваш домен из шага 2, `КЛЮЧ_ПЛОЩАДКИ` и `КЛЮЧ_ПАКОВ` — на строки из шага 1. Всё должно быть в одну строку.

```text
-Server https://audit.hardening-audit.ru -SiteKey КЛЮЧ_ПЛОЩАДКИ -PackPublicKey КЛЮЧ_ПАКОВ -Share \\corp.local\NETLOGON\Hardening
```

При необходимости допишите в конец строки через пробел:

| Добавка | Когда нужна |
| --- | --- |
| `-Schedule Weekly` | Проверка раз в неделю (понедельник) вместо ежедневной |
| `-Proxy http://proxy.corp:3128` | Интернет доступен только через прокси |
| `-CollectIdentity` | Собирать сотрудника за ПК и его доменные группы (только если сбор ПДн согласован) |

### 3.2. Создайте политику

1. На контроллере домена: «Пуск» → введите `gpmc.msc` → Enter. Откроется «Управление групповой политикой».
2. Слева раскройте «Лес» → «Домены» → ваш домен.
3. Правой кнопкой — по «Объекты групповой политики» → **«Создать»** → имя `Харденинг — агент` → OK. Пока ни к чему не привязывайте: это шаг 4.
4. Правой кнопкой по созданной политике → **«Изменить»**. Откроется редактор.

### 3.3. Немедленная задача (установка без перезагрузки)

1. **Конфигурация компьютера → Настройка → Параметры панели управления → Назначенные задания**. Правой кнопкой → «Создать» → **«Немедленная задача (Windows 7 и выше)»**.
2. Вкладка «Общие»:
    - Имя: `Hardening agent install`.
    - «Изменить пользователя или группу» → введите `SYSTEM` → OK. В поле появится `NT AUTHORITY\System`.
    - Отметьте «Выполнить с наивысшими правами».
3. Вкладка «Действия» → «Создать»:
    - Действие: «Запуск программы».
    - Программа или сценарий: `powershell.exe`.
    - Добавить аргументы: `-NoProfile -ExecutionPolicy Bypass -File "\\corp.local\NETLOGON\Hardening\gpo-startup.ps1"`, пробел и строка из 3.1.
4. OK.

### 3.4. Сценарий автозагрузки (обновления)

1. **Конфигурация компьютера → Политики → Конфигурация Windows → Сценарии (запуск/завершение)**. Дважды щёлкните **«Автозагрузка»**.
2. Вкладка **«Сценарии PowerShell»** (не «Сценарии») → «Добавить».
3. Имя сценария: `\\corp.local\NETLOGON\Hardening\gpo-startup.ps1`. Параметры сценария: строка из 3.1.
4. OK → OK. Закройте редактор.

Результат шага: политика «Харденинг — агент» с двумя элементами. Она ещё ни на один ПК не действует.

## Шаг 4. Пилот на 5–10 ПК

Сначала политика включается на нескольких ПК. Если в строке параметров опечатка, проблема будет только у них, а не у 500 машин.

1. Откройте «Пользователи и компьютеры Active Directory» (`dsa.msc`). Создайте подразделение `Харденинг — пилот` и перенесите в него 5–10 ПК из разных отделов. Сотрудники этого не заметят. Другие политики, привязанные к их прежнему подразделению, при этом перестанут на них действовать. Если для вас это важно, привяжите политику к самому маленькому существующему подразделению.
2. В `gpmc.msc` правой кнопкой по этому подразделению → **«Связать существующий объект групповой политики»** → «Харденинг — агент» → OK.
3. Подождите до 2 часов. Чтобы не ждать, на любом пилотном ПК откройте командную строку от администратора и выполните `gpupdate /target:computer /force`. Перезагружать ПК не нужно. На стенде агент встал за 30 секунд.

### Как проверить

На сервере: страница **«Агенты» → блок «Хосты»**. Каждый пилотный ПК должен быть там со свежей «Последней связью». В карточке актива должны появиться результаты проверок и «Паспорт оборудования».

На ПК (PowerShell от администратора):

```powershell
Get-Content C:\ProgramData\HardeningAgent\gpo-startup.log -Encoding UTF8
Get-ScheduledTaskInfo 'Hardening agent' | Format-List LastRunTime, LastTaskResult
```

Правильный журнал выглядит так, `LastTaskResult` равен `0`:

```text
2026-10-30 08:53:27 установлен агент версии 2026.10.30-...
2026-10-30 08:53:43 регистрация (код 0): хост WS2 зарегистрирован на сервере, ключ хоста сохранён в C:\ProgramData\HardeningAgent\host.json
2026-10-30 08:53:54 задача планировщика «Hardening agent» создана (расписание Daily)
2026-10-30 08:53:54 первый прогон запущен
```

Пилот успешен, когда все пилотные ПК есть в «Хостах» и у каждого есть отчёт. Если нет — смотрите раздел «Если что-то пошло не так».

## Шаг 5. Раскатка на все ПК

Политика привязывается к остальным подразделениям волнами. Сервер выдерживает и все 500 ПК сразу: нагрузочный тест принял 1000 хостов за 10,5 минут. Волны нужны для того, чтобы заметить проблему на части парка.

| Волна | Куда привязать политику | Когда идти дальше |
| --- | --- | --- |
| 1. Пилот | Подразделение «Харденинг — пилот» (5–10 ПК) | Все пилотные ПК в «Хостах», у каждого отчёт |
| 2. Один отдел | Подразделение одного отдела (~50 ПК) | Через сутки в «Охвате» больше 90% ПК отдела в статусе «Отчитываются» |
| 3. Все рабочие станции | Верхнее подразделение с ПК: политика действует и на все вложенные | Через 2–3 дня — сверка по «Охвату» |
| 4. Серверы Windows | Подразделение серверов — по согласованию с их владельцами | — |

Политика привязывается так же, как в шаге 4: правой кнопкой по подразделению → «Связать существующий объект групповой политики». Пилотные ПК потом можно вернуть в их подразделения: агент на них останется.

### Как узнать, на каких ПК агента нет

1. На контроллере домена выгрузите список компьютеров (PowerShell):

```powershell
Get-ADComputer -Filter * -Properties OperatingSystem,LastLogonDate |
  Select-Object Name,DNSHostName,OperatingSystem,LastLogonDate,Enabled |
  Export-Csv computers.csv -NoTypeInformation -Encoding UTF8
```

2. На странице **«Агенты» → блок «Охват»** выберите файл `computers.csv` → «Загрузить список».
3. Сервер разложит ПК по статусам: «Отчитываются», «Давно молчат», «Агент не установлен». Нажмите на «Агент не установлен» → «Скачать CSV». Получится список на разбор.

В списке «Агент не установлен» обычно оказываются несколько видов ПК. Первые — выключенные (смотрите «Последний вход (AD)»). Вторые — ПК в подразделениях без политики. Третьи — ПК без доступа к серверу по 443. Записи вида `DC1` или давно удалённые ПК — мусор в AD, а не ошибка агента.

### После раскатки

- Новые ПК, введённые в домен, получат агент сами, пока действует ключ площадки. За неделю до истечения выпустите новый ключ (шаг 1) и замените его в обоих элементах политики (3.3 и 3.4).
- Уже установленные агенты не зависят от ключа площадки и работают дальше.
- Когда выйдет новая версия агента, повторите шаг 2. ПК обновятся при следующей загрузке.

## Linux-машины: Ansible

На Linux групповой политики нет, её роль играет Ansible. Одна команда с компьютера администратора ставит агент на все машины списка по SSH. Ключ площадки — тот же, что для Windows (шаг 1).

Нужно: компьютер с Linux (подойдёт рабочая станция администратора или WSL), с которого вы заходите на серверы по SSH и можете выполнять `sudo`. На самих машинах нужен только `python3`, в Ubuntu, Debian, Astra и RED OS он уже есть.

1. Поставьте Ansible и скачайте плейбук:

```bash
sudo apt install -y ansible
mkdir ~/hardening && cd ~/hardening
curl -fsSLO https://audit.hardening-audit.ru/downloads/hardening-agent-linux.tar.gz
tar xzf hardening-agent-linux.tar.gz --strip-components=3 --wildcards '*/deploy/ansible/*'
ls   # hardening-agent.yml  templates
```

2. Создайте файл `inventory` — список машин, по одной в строке. Можно имена, можно IP-адреса:

```ini
[linux]
srv-db01.corp.local
srv-web02.corp.local
10.0.5.17

[linux:vars]
ansible_user=admin
```

3. Создайте файл настроек. Ключ площадки в нём хранится зашифрованным. Команда спросит пароль для шифрования, придумайте и запомните его:

```bash
{ echo 'hardening_server: https://audit.hardening-audit.ru'
  ansible-vault encrypt_string 'КЛЮЧ_ПЛОЩАДКИ' --name hardening_site_key
  echo 'hardening_pack_public_key: "КЛЮЧ_ПАКОВ"'
} > hardening-vars.yml
```

При необходимости допишите в `hardening-vars.yml` строки — аналоги добавок из шага 3.1: `hardening_schedule: weekly`, `hardening_proxy: http://proxy.corp:3128`, `hardening_collect_identity: true`.

4. Запустите сначала на одной машине (`--limit`), потом на всех. `--ask-become-pass` спросит пароль sudo, `-f 20` задаёт 20 машин одновременно:

```bash
ansible-playbook -i inventory hardening-agent.yml -e @hardening-vars.yml --ask-vault-pass --ask-become-pass --limit srv-db01.corp.local
ansible-playbook -i inventory hardening-agent.yml -e @hardening-vars.yml --ask-vault-pass --ask-become-pass -f 20
```

Результат: в конце строка `PLAY RECAP` с `failed=0` для каждой машины. После этого машины появятся в «Агенты» → «Хосты». Дальше агент запускается сам раз в сутки (таймер systemd). Повторный запуск плейбука безопасен: он обновит агент до новой версии и ничего не сломает.

Проверка на машине: `systemctl list-timers 'hardening-agent@*'` показывает следующий запуск, `journalctl -u hardening-agent@local -n 20` — журнал последнего прогона.

Машины, введённые в домен через sssd, с `hardening_collect_identity: true` присылают сотрудника, который сейчас в системе (или заходил последним), и его доменные группы.

## Если что-то пошло не так

Первое, что нужно смотреть на проблемном ПК, — журнал `C:\ProgramData\HardeningAgent\gpo-startup.log`. Каждая ошибка сценария записывается туда по-русски.

| Что видно | Причина | Что делать |
| --- | --- | --- |
| Нет папки `C:\ProgramData\HardeningAgent` | Политика ещё не дошла до ПК | На ПК: `gpresult /r /scope computer` — в списке применённых должна быть «Харденинг — агент». Нет — ПК в другом подразделении |
| `ошибка: сервер недоступен` | Нет доступа к порту 443 или нужен прокси | `Test-NetConnection audit.hardening-audit.ru -Port 443`; если есть прокси — добавьте `-Proxy` (шаг 3.1) |
| `SHA-256 агента не совпал с опубликованным` | В общей папке старая версия, а на сервере уже новая | Повторите шаг 2 |
| `регистрация (код 1): ... уже зарегистрирован и был на связи` | ПК переустановлен или заменён под тем же именем | «Агенты» → «Хосты» → удалите регистрацию этого имени. ПК зарегистрируется при следующей загрузке |
| `регистрация (код ...)` с сообщением о ключе | Ключ площадки истёк, отозван или скопирован с опечаткой | Выпустите новый ключ (шаг 1) и замените его в 3.3 и 3.4 |
| ПК есть в «Хостах», но отчёта нет; `LastTaskResult` не равен 0 | Прогон агента завершился ошибкой | Пришлите разработчику вывод ручного запуска (ниже) |
| В карточке нет «Паспорта оборудования» | Агент старше 2026.10.30: при загрузке ПК не успевал собрать данные | Повторите шаг 2; следующий прогон пришлёт паспорт |

Ручной запуск агента на проблемном ПК (PowerShell от администратора). Это обычный прогон, как ночью: в конце будет видна причина ошибки.

```powershell
$env:HARDENING_PACK_PUBLIC_KEY = [Environment]::GetEnvironmentVariable('HARDENING_PACK_PUBLIC_KEY','Machine')
$env:HARDENING_PIN_SHA256 = [Environment]::GetEnvironmentVariable('HARDENING_PIN_SHA256','Machine')
```

Удалить агент с одного ПК: выведите ПК из подразделения с политикой, затем выполните `Unregister-ScheduledTask 'Hardening agent' -Confirm:$false` и удалите папки `C:\Program Files\Hardening` и `C:\ProgramData\HardeningAgent`. После этого удалите регистрацию ПК в «Хостах».
